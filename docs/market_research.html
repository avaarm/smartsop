1. Executive summary (TL;DR)

SmartSOP already ships the right foundational product for its niche: a mobile-first SOP builder for industrial and safety-critical work, with photo/video capture, QR codes for equipment, LOTO-specific templates, JHA (Job Hazard Analysis), and simple team pricing. The site says as much — LOTO templates, mobile lockout log, photo/video per step, QR generation, PDF export, in-app messaging, and role-based dev/review. That's a legitimate wedge and it maps cleanly to the "operational SOP" audience that most competitors underserve.

The problem is that four categories are converging on that same buyer and each brings something SmartSOP doesn't yet have:

What's converging

  • protocols.io — an editor with rich components (typed steps, timers, reagents, safety icons), a proper Run mode, versioning with rollback, a task manager tied to the calendar, and an increasingly aggressive AI layer (importer, troubleshooter, translator, discussion summarizer).
  • SafetyCulture / iAuditor — mobile inspections, offline mode, corrective actions, QR-triggered issue reporting, and enterprise integrations (Tableau, PowerBI, SAP).
  • MaintainX — dynamic SOPs with nested logic, procedure-score targets, mobile work-order execution, and 24/7 chat support.
  • Whale / Scribe / Tango / Vidocu / Trupeer / Guidde — AI capture of screen or video that automatically generates step-by-step SOPs.

What SmartSOP must add to compete

  • A real Run mode with progress state, timers, e-signature, and immutable run records — not just "PDF export of the doc."
  • Dynamic / conditional steps (branching by hazard, equipment, or answer).
  • AI SOP generation — from a phone video, an existing PDF, or a spoken narration.
  • Offline mobile execution (the SafetyCulture standard).
  • Approval workflow + audit trail that maps to 21 CFR Part 11, ISO 9001, and OSHA docs.
  • Reagent / consumables / equipment library (call it "Assets") that SOP steps can reference by ID and QR.
  • Analytics — who completed which SOP, avg. run time, deviations, expiring competencies.
Strategic bet. Don't try to out-notebook Benchling and don't try to out-audit iAuditor. Own the "execute a hazardous or high-consequence field procedure and prove you did it right" wedge. That is a defensible position: protocols.io is science-lab shaped, iAuditor is inspection-shaped, MaintainX is work-order-shaped, Scribe/Whale are desk-shaped. Nobody credibly owns "the mobile app you hand to the tech who is about to lock out a switchgear." That is SmartSOP's opening.

3. Deep dive — protocols.io (the primary competitor)

Even though protocols.io's origin story is scientific methods, they've quietly built the reference implementation of what a modern SOP platform looks like. Their product is the specific yardstick your engineer should measure SmartSOP against.

3.1 The three surfaces they lead with

Their marketing site organizes the product around three surfaces — Editor, Workspaces, and File Manager. That trichotomy is worth stealing verbatim: it forces a clean mental model for engineers and buyers.

Editor

  • Create protocols, documents, or collections
  • Advanced components for precision (typed step blocks: reagents, timers, tables, safety icons, section duration)
  • Concurrent (Google-Docs-style) editing
  • Inline commenting on any block; "pinned by author" comments
  • Detailed history & rollback

Workspaces

  • Shared reagent / file library across teammates
  • Workspace-level commenting
  • Fully integrated task manager (calendar-based)
  • Granular sharing (private → workspace → public)

File Manager

  • Any file type, granular permissions
  • Archiving, auditing, exporting
  • Native connectors to Dropbox, OneDrive, Box
  • Enterprise backup

3.2 Run mode — the feature SmartSOP most needs

protocols.io's Run mode is the concept that unlocks everything else. Every published protocol can be "run" as an interactive checklist. When the run finishes, the changes and observations captured during the run are recorded in the File Manager as a run record — an immutable artifact tied to a specific version of the SOP, a specific user, and a specific timestamp. In an industrial SmartSOP context, that run record is your OSHA / ISO / audit evidence. Without it, SmartSOP is a document editor; with it, SmartSOP becomes a system of record.

3.3 The Publish surface

Publishing on protocols.io mints a DOI and archives the document with CLOCKSS and the Internet Archive. You don't need DOIs, but the pattern is worth copying — publishing a signed, versioned, controlled SOP that supersedes the previous version and preserves the previous version for audit is exactly what quality/regulatory buyers look for.

3.5 Editor "advanced components" — the block library

protocols.io calls out these purpose-built blocks that most Word docs cannot express: reagents (with concentration/CAS), timers (with countdown at run time), section durations, temperature ranges, safety icons (toxic, biohazard), tables, expected results. When someone runs the protocol, timers actually count down and reagents actually appear as a materials list at the top of the run.

For SmartSOP the equivalent block library should include: PPE required, Energy source, Isolation device, Authorized person(s), Torque / pressure / temperature spec, Verification photo required, Second-signature required, Lockout tag ID, Hazard class, Return-to-service check. Turning these from "text in a paragraph" into first-class typed blocks is the single biggest UX and value leap you can make.

4. The rest of the competitive set

4.1 SafetyCulture / iAuditor — the incumbent in your buyer's pocket

iAuditor is likely already installed on your target buyer's phone. It nails the mobile inspection form pattern with offline mode, drag-and-drop template builder, photo/video evidence, corrective-action assignment with due dates and priorities, QR-code-triggered issue reporting from anyone (even non-users), and real-time analytics dashboards. Enterprise integrations reach Tableau, PowerBI, and SAP. iAuditor calls its cross-team comms feature "Heads Up" (video messaging). For SmartSOP the takeaway is that offline execution, corrective actions, and QR-scan-to-report are table stakes in this segment, not differentiators.

Where iAuditor is weak (per third-party LOTO reviews): it is described as "an audit tool, not an execution tool" — it documents compliance after work has started, rather than gating unsafe starts. That is exactly where SmartSOP can win.

4.2 MaintainX — the CMMS that ate SOPs

MaintainX now bundles SOPs into work-order execution with nested logic fields (conditional steps that appear based on user input), Procedure Score targets so you can benchmark how well SOPs are being executed, and a mobile-first UI with 24/7 in-app chat support. Their positioning is "SOPs live inside work orders." SmartSOP should ship conditional/branching steps to close this gap — a lockout procedure for a 480V panel and a 4160V panel diverge, and forcing a single linear SOP is a bug, not a feature.

4.3 SweetProcess, Trainual, Whale, Process Street, Waybook, SystemHUB, Way We Do

These are the office-SOP tools. The features they've normalized that SmartSOP should assume are expected: role-based access with real-time collaborative editing, version control with change tracking, process maps / visual flowcharts, quiz-based competency verification with pass/fail tracking, completion analytics (who read it, who acknowledged it, how long they took), reminders + notifications, and customizable dashboards. Whale specifically emphasizes AI-assisted writing and auto-generated quizzes from a doc. Way We Do popularized the phrase "activated checklist" for a policy that has been turned into a runnable procedure — exactly SmartSOP's product story.

4.4 Video-to-SOP tools — Scribe, Tango, Vidocu, Trupeer, Guidde, MagicHow, Kommodo, Screenapp

This is the fastest-moving segment and the one most likely to reshape user expectations for SmartSOP in the next 12 months. Scribe and Tango pioneered "install extension → do the task → get a formatted SOP with annotated screenshots." Vidocu goes further: upload any video (screen, Zoom, phone), get back both a written SOP and a polished tutorial video with AI voiceover in 30+ languages and translated subtitles. Trupeer generates presenter-style training videos with AI avatars from a screen recording. Guidde produces narrated how-to videos. IT Glue's "Smart SOP Generator" (Cooper Copilot) already brands its capture-and-generate flow with the "Smart SOP" name — a namespace collision worth noting.

Name collision. "Smart SOP" is used by at least three products in this category (Kaseya IT Glue's Smart SOP Generator; a Microsoft AppSource app; the smartsop.com you own). If the app is early enough, consider whether the brand is defensible in your target vertical, or whether a modifier ("SmartSOP for Safety," "SmartSOP Field," "SmartSOP LOTO") sharpens positioning.

4.5 The scientific ELN adjacency — Benchling, LabArchives, SciNote, Colabra, eLabFTW, Labguru

Not directly comparable, but two takeaways matter. First, Benchling's product design principle — that data logging from instruments should be automatic and the notebook is where science gets kept, not where it gets done — is a warning: don't build SmartSOP as a mode the tech has to reinvent every shift. Second, none of these ELNs seriously address mobile bench execution, 21 CFR Part 11 e-signature at the point of work, or offline runs. That is the same gap operational tools like iAuditor leave open. SmartSOP owns the intersection.

6. Where SmartSOP wins today & where it loses

Where SmartSOP wins

  • LOTO + JHA + PPE are first-class concepts, not generic form fields. protocols.io doesn't touch this; iAuditor treats it as one form template among thousands.
  • Prefilled LOTO templates and authorized-person identification put a competent skeleton in front of a customer on day one.
  • Mobile Lockout Log with entry linked to procedure — this is a specific execution artifact the incumbents don't produce as cleanly.
  • Per-seat pricing at the low end ($1.99-$5/seat) is dramatically friendlier for SMB acquisition than iAuditor, Trainual ($249/mo), or protocols.io Premium (sales-gated).
  • Industry-specific onboarding language across nine sectors gives the marketing site clear-buyer resonance in a category that mostly sells to "everyone."

Where SmartSOP loses

  • No real Run mode / run record. The output today is a PDF of the doc — not a signed, versioned artifact of "who executed which version, when, with what evidence."
  • No conditional steps. A 480V lockout and a 4160V lockout aren't the same procedure and shouldn't share a linear SOP.
  • No AI capture. Every prospect will demo a competitor that lets them shoot a phone video and get a formatted SOP back. SmartSOP without this in 2026 reads as "old."
  • No offline mode. iAuditor's offline story is a huge trust builder for underground, remote-site, and refinery-floor work; SmartSOP's absence is a losable-deal item.
  • No enterprise controls (SSO, audit trail, e-signature, HIPAA, VPC). The moment a real quality/regulatory buyer asks, the deal stalls.
  • No integrations. The product page mentions none. iAuditor connects to SAP; protocols.io to Dropbox/OneDrive/Box; MaintainX is a CMMS bridge. Isolation kills expansion revenue.
  • No analytics. Buyers pay for dashboards more readily than for documentation.
  • Version control is described as "SOP history documentation" — that reads like "we save old files," not like "you can compare v3 to v4, roll back, and audit who changed what."

7. Prioritized feature roadmap

Tagged MUST = ship in the next release to remain credible; SHOULD = ship inside 6 months to be competitive; NICE = defensible differentiator; AI = AI-powered.

7.1 Phase 1 — Table stakes (next release)

  1. MUST Run mode. A published SOP can be launched as an interactive session. State per step is one of pending / in-progress / complete / skipped / deviation. Each step captures who did it, when, and any evidence (photo/video/reading). The completed session produces an immutable, versioned Run Record tied to (SOP version, user, timestamp, org). This one feature does more than any other to turn SmartSOP from a document tool into a system of record.
  2. MUST Typed step blocks (see §3.5). Ship the LOTO-specific block library first: PPE required, Energy source, Isolation device, Authorized person, Verification photo, Second signature, Torque/pressure/temperature spec, Lockout tag ID, Hazard class, Return-to-service check. A step block should render differently in the editor (a form) and at run time (an actionable widget).
  3. MUST Version control with diff and rollback. Users need to see "what changed between v3 and v4," roll back to a prior version, and know which version was live when a run was executed.
  4. MUST Approval workflow. Author → Reviewer → Approver → Published. Each transition captures user, timestamp, and comment. This is what quality and safety directors actually buy.
  5. MUST Concurrent editing + inline comments. Two authors, one document. Comments anchored to blocks, resolvable, with a "pinned by author" answer pattern borrowed from protocols.io.
  6. MUST Offline mobile execution. The tech in a substation basement has no LTE. Local cache of assigned SOPs, evidence capture stored locally, sync-on-reconnect with conflict resolution. This is table stakes in your segment.

7.2 Phase 2 — Competitive parity (6 months)

  1. SHOULD AI Import from Word/PDF. Drag a legacy SOP in; get a structured SmartSOP back with typed blocks inferred (PPE list, hazard callouts, step numbering). This is the single feature that unblocks migration and closes sales.
  2. SHOULD AI Video/voice → SOP. The competency floor for authoring in 2026. A supervisor shoots a 4-minute phone video walking through a lockout on the CNC machine and speaks the steps aloud; SmartSOP returns a draft SOP with steps, timestamps, extracted key frames as step photos, and a machine-generated title. Even a rough first pass wins deals.
  3. SHOULD Conditional / branching steps. "If voltage > 600V, execute steps 12-18. Else skip to 20." Or "if answer to Step 4 = No, halt and notify supervisor." Every step gets a rule engine.
  4. SHOULD Asset / equipment library. Every piece of equipment gets a record: id, location, hazard class, energy sources, associated SOPs, QR code. Scanning the QR from the phone opens the correct SOP for that specific asset (this is what makes the QR feature actually useful in the field, not just a link).
  5. SHOULD Task manager / scheduling. Assign a run to a user or a role, on a schedule (monthly PM), with a due date; the run shows up on a calendar view and drives a to-do list. This is where protocols.io went, and it turns SmartSOP from a document library into an ops platform.
  6. SHOULD Corrective actions / issue capture. During a run, "flag deviation" opens a mini-form (what happened, evidence, severity), creates a follow-up task, and routes to the right owner. iAuditor's version of this pattern is the reason enterprise buyers stay.
  7. SHOULD Analytics dashboard. Completion rate by SOP, by shift, by user; average run duration; deviation count; expiring competencies. Ship 4 charts that a plant manager will screenshot for their weekly meeting.
  8. SHOULD Storage integrations. Google Drive, OneDrive, Box, Dropbox for evidence backup and doc source-of-truth. The protocols.io pattern.
  9. SHOULD AI Semantic search ("SOP Finder"). Natural-language queries that resolve past keyword mismatches. This is one of the highest-value / lowest-cost AI features to ship.
  10. SHOULD AI Bilingual EN-ES rendering. Every SOP gets an auto-translated Spanish view that the tech can toggle on the phone. Rendering-time, not authoring-time, so authors only maintain one source.
  11. SHOULD Training + competency. Assign an SOP as a training module; require read + quiz + acknowledgment before the user is credentialed to run it. Track expirations (annual re-certification).
  12. SHOULD SSO / SAML + role-based access. The moment you sell to a company > 100 seats, this is non-negotiable.

7.3 Phase 3 — Enterprise / regulated (9-12 months)

  1. SHOULD 21 CFR Part 11 e-signature. Per-step or per-approval electronic signatures with two-factor verification, meaning-of-signature capture, and an immutable audit trail. Required to sell into pharma, medical device, food safety.
  2. SHOULD Full audit trail. Every field change on every record, forever, exportable. Also required for CFR Part 11, ISO 9001, GxP.
  3. SHOULD HIPAA-compliant deployment for healthcare-facing customers.
  4. SHOULD Public REST API + webhooks. Read/write SOPs, runs, and assets. Webhooks for run-complete, deviation-flagged, SOP-published. Enables CMMS integration (MaintainX, UpKeep, Fiix), BI integration (Tableau, PowerBI), and iPaaS (Zapier, Make).
  5. NICE VPC / on-prem deployment for enterprise regulated customers who need data locality.
  6. NICE SCIM provisioning for Okta/Azure AD lifecycle.

7.4 Phase 4 — Defensible differentiators

  1. NICE AI Deviation Assistant. When a tech marks a step as deviation, the AI proposes: known root causes, recommended follow-up steps, whether to escalate to supervisor, and which past deviations match. Trained on the org's own run-record history.
  2. NICE Regulatory pack templates. Prebuilt SOP templates aligned to OSHA 1910.147 (LOTO), OSHA 1910.146 (confined space), NFPA 70E (arc flash), ISO 45001, HACCP, HAZWOPER, GxP. Shipping these as opinionated starting points wins categorical trust.
  3. NICE AI Compliance drift alerts. Ingest a customer's OSHA / ISO reference doc; SmartSOP flags where their SOPs no longer conform.
  4. NICE Photo-of-lockout verification. Second worker takes a photo of the applied lock/tag; the run cannot advance until a peer signs off. This is a real operational moat.
  5. NICE Voice-first execution. Hands-free run mode: read the step aloud, capture verbal confirmation, allow "next" / "flag" voice commands. Enormous in gloved-and-goggled environments.
  6. NICE Wearable / hard-hat camera integration. RealWear, Vuzix, etc. — the front-line workflow market is starting to standardize here.
  7. NICE AI AI SOP Auditor. Uploads a customer's existing SOP library and returns a gap report: missing PPE, missing energy sources, ambiguous steps, stale references. Immediately valuable during a sales cycle.

8. UI / UX recommendations

8.1 Three-surface information architecture

Adopt protocols.io's mental model but rename for your buyer: Library (your SOPs), Workspace (people, roles, assets, tasks), Records (runs, evidence, exports, audit). Every screen should always answer "am I authoring, am I executing, or am I auditing?" — three modes, three visual treatments.

8.2 The editor

Notion / Google-Docs block model. Slash-command insertion of typed step blocks (/ppe, /timer, /lockout, /photo-required). Left rail = section outline with per-section duration estimate. Right rail = comments + version history. Top status pill = current state (Draft / In Review / Approved / Published) and the version number. Save is autosave. "Publish" is an explicit gated action that runs the approval workflow.

8.3 Run mode — the most important screen in the product

Full-screen on mobile, one step per screen, giant tap targets, thumb-reachable action buttons. Persistent top bar shows SOP name, current step / total, and a big red HALT button that captures reason and notifies. Persistent bottom bar has three actions: Next, Add Evidence, Flag Deviation. Step content is designed for a gloved hand at arm's length: 20pt+ type, single primary CTA, no accidental swipes. If offline, a subtle banner shows "Working offline — 3 items pending sync." If the SOP requires a second signature at this step, the Next button is disabled until a second user authenticates.

8.4 Design language for the industrial user

  • Legibility over polish. Assume bright sun, oily gloves, prescription safety glasses, and possibly cold hands. Minimum body font 16pt on mobile, 20pt in run mode. All CTAs at least 48×48pt tap area.
  • Colored status is a vocabulary, not decoration. Pending gray, in-progress amber, complete green, deviation red, skipped hatched-gray. Consistent everywhere. Avoid using red for anything else.
  • Photo/video capture is one tap from any step. The camera opens with the step name as an overlay on the frame so the resulting photo is self-documenting.
  • Timers count down in the corner, buzz on completion, and cannot be skipped without a "override with reason" confirmation.
  • QR scanner is on the home screen — the workflow "scan the equipment → the correct SOP opens" is the marquee moment, not buried three levels down.
  • Bilingual toggle in the top bar. One tap flips English ↔ Spanish for the entire run.

8.5 Empty states as onboarding

The empty Library should not be empty — pre-load 6-10 opinionated LOTO/JHA/safety templates by industry, so a new tenant sees value in the first 30 seconds. Include a clearly labeled "import your existing PDF/Word SOPs" upload target with the AI importer wired in.

8.6 Admin console

Buyers who evaluate SmartSOP will demo the admin as much as the user experience. Ensure the admin console can: manage users / roles / groups; assign SOPs to roles; view completion analytics; export records; configure SSO; set retention policies; brand the tenant (logo, colors, PDF export template). The PDF export template is under-loved — customers will run reports for OSHA, and a branded, compliant PDF is often the artifact they're actually paying for.

10. Compliance & enterprise readiness

SmartSOP's target verticals (energy, manufacturing, healthcare, construction, public works) all have regulated buyers. Ignoring compliance closes the ceiling on deal size and shortens the sales cycle for competitors.

  • OSHA 1910.147 (LOTO). Already implicit in your product; make it explicit. Ship a certification / template pack labeled with the standard.
  • OSHA 1910.146 (Confined Space). Adjacent template pack — same buyer.
  • NFPA 70E (Arc Flash / Electrical Safety). Utilities and industrial buyers care intensely.
  • ISO 9001 / ISO 45001. Controlled document workflow, audit trail, approval history.
  • 21 CFR Part 11. E-signature, meaning-of-signature, immutable audit trail. Required for pharma / medical device / clinical. This is the single most valuable compliance certification you can pursue.
  • GxP / GMP. Comes with CFR Part 11 investment.
  • HIPAA. For any healthcare-adjacent customer.
  • HACCP. For food safety and hospitality — a template pack + a "critical control point" typed block is enough to open the food-processing market.
  • SOC 2 Type II. Non-negotiable for any deal above SMB. Start the audit now if it hasn't started.
  • Data residency. US-primary, EU option (Frankfurt or Dublin) for pharma multinational deals.

11. Positioning & go-to-market angle

11.1 The one-sentence pitch

SmartSOP is the mobile-first SOP platform for safety-critical field work — the app you hand to the tech who's about to lock out a switchgear, and the system of record you hand to your OSHA auditor.

11.2 What that positioning implies

  • Lead with LOTO / JHA. Don't try to sell "SOPs for everything." Own a category, then expand.
  • The hero demo is Run mode on a phone, not the editor on a laptop. Every competitor's marketing site shows a laptop editor. Showing a gloved hand tapping a phone in a substation is instantly differentiated.
  • The hero artifact is the audit-ready run record. Sell to safety directors and quality directors, not IT.
  • Bilingual EN-ES is a wedge, not a feature. A single line on the homepage — "Every SOP in English and Spanish, automatically" — resonates with US construction, agriculture, hospitality, and food-processing buyers.
  • Sell industry packs, not generic seats. "SmartSOP for Electrical Utilities," "SmartSOP for Food Processing," each with a preloaded template library and the right typed blocks.

11.3 Pricing tune-up

Your published tiers are attractive at SMB. Add two things:

  • A free tier (single user, up to 5 SOPs, watermarked PDFs). protocols.io shows how much virality comes from a real free plan; you don't need to be as generous, but "free forever, 1 user, 5 SOPs" is powerful.
  • An Enterprise plan that gates SSO, audit trail, e-signature, API, VPC, and dedicated CSM. Contact-sales pricing is fine. This is the plan that lets a $50k ACV deal close.

11.4 Integrations to prioritize (roughly in this order)

MaintainX (CMMS), UpKeep (CMMS), Fiix (CMMS), ServiceNow (ITSM), Microsoft Teams (notifications), Slack (notifications), Google Drive / OneDrive / Box / Dropbox (evidence backup), Okta / Azure AD (SSO), Tableau / PowerBI (analytics export), Zapier / Make (long-tail).

12. Risks & things to validate

Risks

  • Name collision. "Smart SOP" is used by IT Glue and by other apps. Weakens SEO and defensibility. Consider a distinctive product name or a modifier tied to a vertical.
  • Feature scope creep. Everything above is temptation. The disciplined move is Phase 1 in full, then Phase 2, then earn Phase 3 with revenue.
  • Compliance certification cost. SOC 2 + 21 CFR Part 11 is a real budget line. Sequence carefully.
  • Video/AI infra cost. Video-to-SOP is compute-heavy. Cap monthly minutes per plan; charge overages.
  • Competitor bundling. MaintainX is likely to bundle SOP + work order for free as their moat. Your defense is depth in safety-critical, not breadth in maintenance.

Things I recommend you validate with 5 customer interviews

  • Is Run mode + Run Record actually the artifact your safety director wants for OSHA — or do they want a specific PDF format your current export already produces?
  • Which typed step blocks are the top 5 they'd use? (Ship those, then the rest.)
  • How often do they need offline execution — daily, weekly, exceptional?
  • What's the migration story — how many legacy Word/PDF SOPs, and is AI import worth paying for?
  • Is 21 CFR Part 11 an actual buying requirement or a nice-to-have? (Answers vary wildly by vertical.)
